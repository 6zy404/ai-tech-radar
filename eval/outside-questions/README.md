# 外部出题：给搜索和问雷达写问题

`eval/search/queries.json` 和 `eval/ask/questions.json` 里的题都是做这个功能的人
对着全部内容写的，所以几乎全部通过——这说明流程能跑，但分不出好坏。这个目录
收集**没看过站点内容的人**写的题，报告里单独统计（搜索是 `outside` 分组，
问雷达是 `author: "outside"`），也永远不用来调参数。

## 给出题人（请把这一节和 `template.csv` 发给对方）

你不需要知道这个网站上有什么，也**请不要先去浏览它**。想象你关心 AI 技术，
想查点东西：

- **搜索**：你会在搜索框里敲的几个词。
- **问雷达**：你会问一个懂行的同事的一句话。

（只看格式，别看内容：换到别的领域，搜索像「降噪耳机 通勤」，提问像
「新手第一台相机该怎么选？」。）

请在 `template.csv` 里每行写一个（Excel 可以直接打开），大约 20–30 条就很好。
表格里特意没放示例，免得带偏你的写法：

| 列       | 填什么                                       |
| -------- | -------------------------------------------- |
| `用在`   | `搜索`、`问雷达` 或 `都行`                   |
| `问题`   | 原样写你会输入的内容                         |
| `想知道` | 一句话说明你真正想找什么，帮标注的人理解意图 |

几条建议：

- 写你**真的**会问的，不用照顾网站能不能答上来——答不上来的题同样有用。
- 可以问得很宽，也可以问得很具体。
- 有一类题特别有价值：**网站大概只能答一半**的，比如同时问两件事。

## 给标注的人（站点所有者）

出题人交回表格后：

1. 每条题的编号用 `o` 开头（`o01`、`o02`…），与开发者写的题分开。
2. 问雷达的题加进 `eval/ask/questions.json`，带上 `"author": "outside"`：
   - 站内能答：`expected` 填好的回答应当引用的条目（`T:` / `S:` / `K:` + 公开
     slug），引用其中任意一条就算有依据。
   - 站内答不了：`expected` 为空，正确答案是固定拒答语。
   - **只能答一部分**：再加 `"kind": "partial"`，`expected` 填覆盖到的那部分
     条目。自动检查只判「没有整题拒答、引用了相关条目」；有没有说清楚站内缺
     什么，要读结果文件里的 `partialToRead`。
3. 搜索的题加进 `eval/search/queries.json`，`"split": "outside"`，`relevant`
   填应当被搜到的条目；站内没有的就留空。
4. 标注时可以看站点内容——出题要避开内容，标注恰恰需要它。
5. 跑 `npm run eval:ask`（会调用真实接口，产生费用）和 `npm run eval:search`，
   把 `outside` 的结果写进对应的 README。

`partial` 题型和 `author` / `outside` 分组是 2026-09-29 加的，此前的题都算
`builder`。
